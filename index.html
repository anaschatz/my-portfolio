Flagship case study · ShortsEngine

A video is not done just because it rendered.

Production-hardening prototype

ShortsEngine explores how an AI-assisted media pipeline can keep claims, source evidence, render artifacts, review decisions, and release state connected from ingest to export.

Repository Verified showcase

Problem

Generated metadata can say “success” while the video is visibly wrong.

A production tool has to validate the artifact, preserve provenance, surface uncertainty, and stop unsafe or low-confidence results before publishing—not only produce an MP4.

My role

Product direction, architecture, implementation, evaluation, and iteration.

I built the project as an undergraduate research prototype. I used Codex as an implementation and review accelerator; I owned the product decisions, system boundaries, verification criteria, tests, and the decision to accept or reject each change.

End-to-end workflow

One job model, three production paths, one release decision.

  1. 01Ingest

    Accept local media or structured inputs and validate file, path, and request boundaries.

  2. 02Route

    Select football, motivational editorial, or original narrated animation workflow.

  3. 03Analyze

    Run domain-specific extraction behind provider contracts and record evidence.

  4. 04Plan

    Create a validated edit plan rather than sending untrusted model output directly to rendering.

  5. 05Render

    Produce deterministic vertical-video artifacts through FFmpeg and animation tooling.

  6. 06Verify

    Run rendered QA, route uncertainty to human review, and fail closed when evidence is incomplete.

  7. 07Release

    Export only an approved artifact with its review and verification evidence attached.

Architecture

Thin HTTP boundaries around explicit domain services.

The Node.js runtime owns orchestration and state. Optional Python tools are isolated behind adapters, so transcription or upscaling can fail without taking ownership of job lifecycle.

Production boundary

Implemented now versus designed next.

This distinction is deliberate: the current repository is a strong local prototype, not a finished multi-user SaaS.

Concern Implemented and tested now Next production milestone
Persistence Local/SQLite job and artifact state with protected transitions. Wire the existing PostgreSQL schema to a selectable runtime adapter.
Work claiming Single-process durable lease queue, retries, recovery, cancellation, and terminal-state protection. Prove multi-instance claiming, distributed cancellation, and dead-letter operations.
Artifacts Safe path boundaries plus object-storage contracts and cloud-adapter checks. Operate a managed object store with lifecycle, retention, and recovery evidence.
Human review Low-confidence football results produce candidates that can be selected, rejected, or regenerated. Validate reviewer identity and conflicting decisions in a staged multi-user environment.
Render limits Per-user daily, per-user concurrent, and global concurrent limits; idempotent replay avoids double charging a slot. Enforce quotas consistently across multiple workers and instances.
Telemetry In-process latency, duration, failure, retry, and cache-hit metrics with redacted health output. Durable metrics, provider billing reconciliation, and authoritative per-job cost attribution.
